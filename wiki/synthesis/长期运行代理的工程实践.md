## 结论先行
**长期运行代理（数小时乃至数天的自主任务）能否成功，不是模型能力问题，而是 harness 工程问题。** Anthropic 两篇博客与 Nous Research 的 Hermes 重构（2026-09）实证结论一致：让 Agent 持续产出，靠的是——任务分解、结构化工件交接（进度文件+git+功能清单）、干净状态（每会话结束可合并主分支）、端到端可验证（浏览器自动化以用户身份点测）、独立评审（评估器抵消自我评估偏差）。而且这套脚手架不是越厚越好：**模型变强，harness 就应做减法**。

把规模从个位数代理推到 **1,393 个代理**后，原理仍然成立，但要补两项机制（**工作副本隔离 + 可机械校验的接口契约**），并且暴露出一条不可省的红线：**人类评审可以被推到最后一环，但推不掉**——Hermes 的既有测试全绿，仍漏掉了两类真实回归。

## 证据与演化脉络

### 从"跨会话编码"到"自主全栈构建"
| 维度 | 第一篇（2025-11） | 第二篇（2026-05） |
|---|---|---|
| 目标 | 跨上下文窗口持续编码 | 一次提示、数小时自主构建全栈应用 |
| 架构 | 初始化代理 + 编码代理 | planner → generator → evaluator（GAN 启发） |
| 上下文策略 | 每会话新开（实质 reset） | 单会话 + 自动压缩（Opus 4.5 自愈焦虑） |
| 验证方式 | 显式提示浏览器自动化（Puppeteer） | 评审代理持 Playwright 以用户身份点测 + 硬阈值 |
| 主观质量 | 未涉及 | 4 条评分标准让"好看吗"可评分，few-shot 校准 |

### 第三个数据点：从个位数代理到 1,393 个（Nous Research，2026-09）
| 维度 | Anthropic 2025-11 | Anthropic 2026-05 | Nous 2026-09 |
|---|---|---|---|
| 任务 | 跨窗口持续编码 | 自主构建全栈应用 | 百万行代码库重构 |
| 代理结构 | 初始化 + 编码（2 类） | planner → generator → evaluator | [[代理编排树]]：三层、1,393 个子代理、峰值 218 并发 |
| 时长 / 成本 | 多次会话 | 6 小时 / $200 | 19 活跃小时 / $19.3k（人工估算 $150k–$1.8M） |
| 结果 | 跨会话不丢进度 | 可玩的应用 | 非测试 Python −34.4%；>5,000 行文件 37 → 6 |
| 验证方式 | 浏览器自动化点测 | 评估器打分 + 硬阈值 | 冻结基线对比 + 接口逐字节一致 + 每步 commit |
| 评审者 | 编码代理自检 | 独立评估器代理 | **人类社区两轮评审**（测试漏掉了真实回归） |

结论：原理不变、机制要补。规模上去之后被改写的不是模型，而是三件事——**工作副本的隔离、接口的可机械校验、以及人类评审的位置**（从"逐步监督"退到"最后一道闸门"，但没有被移走）。

### 沉淀的工程机制（对应概念页）
- **[[上下文焦虑]] → [[上下文重置]]**：compaction 保连续但给不了干净起点；重置换干净桌面，靠工件交接状态。
- **[[自我评估偏差]] → [[生成器评估器循环]]**：执行与评审分离，"把怀疑调进独立评估器"远可行于"让生成器自我批评"。
- **主观可验证化**：把"这设计好不好"改写为"符不符合我们的设计原则"（设计质量/独创性/工艺/功能性），让 [[可验证性]] 从"代码专属"扩展到审美领域。
- **[[harness（代理框架）]] 承重思想**：每个组件都是"模型自己做不到"的假设，逐一移除做对照实验找出承重件。
- **[[代理编排树|隔离与契约]]**：工人各用一份独立工作副本（git worktree）互不覆盖；同时把"必须保留的接口"写进任务书——并行度越高，越依赖可机械检查的契约而非对话共识。协调者只写任务书、读报告、合并分支，自己不编辑源码。
- **[[行为保持重构|行为保持]]**：用冻结基线比对失败 + 接口逐字节一致，把"没有改变行为"变成可检验的事实；每步验证后 commit，让崩溃退化为可恢复的中断。
- **[[技能累积|程序性记忆]]**：把"被纠正的做法"自动固化成可读技能文档，使 1,393 份任务书无需人类逐个交代——**harness 在变薄，技能在变厚**。
- **代码库本身也是 harness**：一次重构同时降低了代理的查找成本（平均每次符号查找 2,218 → 993 token，见 [[代理可读性]]）。

### 成本与收益（真实数据）
- Retro 游戏制作器：solo 20 分钟/$9（核心玩法坏）vs full harness 6 小时/$200（可玩）→ **20 倍成本换"能玩"**。
- DAW：4 小时/$124.70，QA 抓"display-only 功能 / 录音 stub / 无 EQ 曲线图"等最后一公里问题。
- 结论：多代理评审贵，但让"表面上像样、实际坏掉"的应用变成"真能用"，代价不小但物有所值。
- Hermes 重构（Nous）：$19.3k（含后续约 $25k）/ 19 活跃小时，换掉人工估算 $150k–$1.8M 的清理工作，约 1% 成本、1% 时间（**不含人工评审**）——规模化把"永远排不上日程"的脏活变成可执行项，见 [[被推迟工作的经济学]]。

## 争议 / 矛盾
- **单代理 vs 多代理**：第一篇留作未决；第二篇用"评估器只在任务超出模型 solo 可靠范围时有价值"给出条件性答案——边界随模型能力外移，这不是永久裁决。
- **harness 是否会过时**：一种看法是模型越强脚手架越可弃；作者观点是空间只会**移动**不会缩小——总有超出基线、需要更复杂组合的新任务。两者其实一致：给同一任务做减法、为更难任务做加法。Hermes 提供了后一半的极端样本：同一套原理推大 3 个数量级，需要**新的**承重件（隔离、契约、共享语言服务器）。
- **自动化是否消除了人工验证**（新增分歧）：Anthropic 路线把评审外包给评估器代理；Hermes 路线证明评估/测试层会漏（公共 API 删除、批量重写的语义漂移），最后仍靠人类社区两轮评审兜底。根据现有证据的折中判断：**被执行的部分可以自动化，行使判断权的部分至少现在不能**——差别只在人站在哪一环。
