## 一句话定义
file over app：**数字资产若要持久，就必须是你能控制的文件**（格式易检索、易读取），而不是困在某个应用生态里的数据。Obsidian 的"库就是文件夹"正是这一哲学的产物。

## 展开解释
- **应用会死，文件不会**：应用会倒闭、转手、改条款、删功能；只要数据是标准格式的本地文件，迁移成本就只是换一个编辑器。
- **格式即锁定**：非标准 Markdown、专有语法、封闭 API 是慢性锁定——今天方便一步，明天被套十年。标准 Markdown + 本地文件 = 随时可跑。
- **与 [[封闭生态]] 的关系**：文件优先是用户的持久反制——平台换得走应用，换不走文件。App 时代的"截图传播"（[[截图传播]]）、"链接死亡"（[[封闭生态]]）都是数据被平台扣押的症状；文件优先把主权留在本地。
- **反模式对照**：云协同（如 Google Docs/Notion）把体验和数据一起托管；Ango 的做法是"本地文件 + git/同步工具 + 静态发布"——体验靠工具拼装，数据永远自持（[[我如何使用 Obsidian（Steph Ango）]]）。
- **与 LLM 协作的契合**：本仓库（[[LLM Wiki 模式]]）依赖于文件优先——LLM 写的全部是 markdown 文件，git 版本化；人可以用任何工具（Obsidian、CLI、任何编辑器）读取和维护。原始来源层 raw/ 也践行"文件是真相源头"。

## 反例 / 边界
- 文件优先 ≠ 拒绝任何后端：同步（Obsidian Sync/git）、发布（Jekyll/Quartz）仍是服务——但它们是**可替换的管道**，不是**数据容器**。区分：数据在谁手里，决定权就在谁手里。
- 协作密度高时（多人实时编辑同一文档），本地文件方案的摩擦上升——这是[[个人工单系统|工具分工]]般的取舍，不是绝对真理。
